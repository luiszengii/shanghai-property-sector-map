# 楼盘资料维护与公开发布指南

本指南是 Agent 读取、研究、录入、修改和发布楼盘资料时的强制操作说明。

用户界面统一使用“楼盘资料中心”。架构文档和代码中的 `source ledger`、`source-ledger` 指底层私有来源、字段证据、不可变修订和发布裁定模型。

## 1. 开始前必须阅读

按任务范围依次阅读：

1. `AGENTS.md`
2. `CONTEXT.md` 的“来源治理”
3. 本指南
4. `docs/adr/0040-keep-source-ledger-local-until-authenticated.md`
5. `docs/adr/0041-use-record-revisions-and-ledger-snapshots.md`
6. `docs/adr/0042-review-agent-research-batches-before-merging.md`
7. `docs/adr/0043-keep-private-ledger-and-generate-public-projection.md`

如果任务涉及板块身份、边界或板块数据源，还必须完整阅读 `docs/SECTOR-BOUNDARY-PLAYBOOK.md`。

如果任务涉及小红书原始数据、清洗数据或观点材料，还必须完整阅读 `docs/XHS-DATA-GUIDE.md`。

## 2. 数据不是一层，而是三层

### 2.1 固定公开目录

位置：

- `src/content/project-leads.ts`
- `src/data/project-locations.ts`

这里保存地图已经公开使用的 46 个楼盘身份、名称和固定位置元数据。它们受 Git 版本控制，是当前公开地图的基础目录。

不要因为私有研究出现新名称、地址或点位，就直接覆盖固定公开目录。先形成来源和证据记录，完成核验与人工裁定，再通过明确的数据迁移修改公开目录。

### 2.2 私有研究底稿

位置：

- `outputs/source-ledger/ledger.json`

用途：

- 保存可复用来源
- 保存来源与具体楼盘字段之间的证据关系
- 保存私有备注、许可判断和待核验线索
- 保存不可变修订
- 保存资料版本快照
- 保存 Agent 研究批次及逐条验收进度

该目录被 `.gitignore` 排除，只允许本机开发环境读写。它可能包含未获公开许可、尚未核验、存在冲突或只供研究使用的材料，因此不得整体提交到 Git，也不得让生产页面直接读取。

### 2.3 公开产品投射

公开产品投射是从私有研究底稿中筛选出的最小数据集合，应该受 Git 版本控制并由地图 APP 使用。

只有同时满足以下条件的字段才能进入公开投射：

1. 证据的发布状态是 `可公开投射`
2. 证据未超过 `reviewDueAt`
3. 证据引用的来源允许用途是 `可公开引用`
4. 字段已经过用户或明确授权的人工裁定
5. 输出中不包含私有备注、历史修订、内部比较、受限摘录或研究快照

公开文件固定为：

- `src/data/project-public-projection.json`

生成器固定为：

- `scripts/build-public-project-data.mjs`

Agent 不得手工把 `ledger.json` 复制到 `src/data/`，也不得直接编辑公开投射来绕过资料版本和人工审核确认。

## 3. 当前私有数据结构

`ledger.json` 的根结构为：

```json
{
  "schemaVersion": 1,
  "sources": [],
  "evidence": [],
  "snapshots": [],
  "researchBatches": []
}
```

### 3.1 来源 `sources`

来源是可被多条证据复用的原始资料，例如政府网页、开发商正式文件、开放数据或允许使用的项目页面。

每个来源包含：

- 稳定的来源 `id`
- `currentRevisionId`
- 不可变的 `revisions`

每次修改标题、发布者、链接、来源类型、许可状态、允许用途或备注时，都必须追加新修订，不能覆盖旧修订。

允许用途固定为：

- `可公开引用`
- `仅限事实核验`
- `仅限本地研究`
- `禁止使用`

### 3.2 字段证据 `evidence`

证据记录把一个来源绑定到一个楼盘的具体字段和值。

关键字段：

- `objectType`: 当前只能是 `project`
- `objectId`: 必须对应固定公开目录中的楼盘 ID
- `field`: 被支持的字段名称
- `value`: 当前观察到的字段值
- `sourceId`: 必须引用已登记来源
- `confidence`: 证据支持强度
- `publicationStatus`: 发布裁定
- `observedAt`: 信息观察日期
- `reviewDueAt`: 下次复核日期，可以为空
- `note`: 仅限本地的判断、冲突和后续任务

证据置信度固定为：

- `已核验`
- `高`
- `中`
- `低/线索`

发布状态固定为：

- `仅本地研究`
- `待裁定`
- `可公开投射`
- `禁止公开`

置信度、许可状态、复核期限和发布状态是四个独立判断。高置信度或已核验不代表允许公开。

### 3.3 资料版本 `snapshots`

资料版本冻结创建时所有来源和证据的当前修订 ID，用于复现某一时刻的状态。

资料中心支持创建和浏览资料版本，并逐条预览哪些冻结证据会进入公开数据、哪些被发布状态、来源用途或复核日期拦截。当前尚未实现把当前私有记录恢复到旧版本；Agent 不得声称资料版本已经“可恢复”，也不得通过删除后续修订来模拟恢复。

### 3.4 研究批次 `researchBatches`

研究批次用于装载 Agent 提交、等待人工裁定的一组来源和证据候选，状态固定为：

- `待裁定`
- `已合并`
- `已退回`

当前已实现：

- 通过受验证的导入脚本创建 `待裁定` 批次
- 在“楼盘资料中心”的“研究验收版本”区域浏览、搜索和筛选候选
- 逐条勾选或取消验收，并在刷新页面后保留进度
- 仅在全部候选完成验收后，把整个批次并入当前私有来源和证据修订

验收勾选只记录人工检查进度，不会自动把候选来源或证据并入当前记录。人工点击“并入当前台账”后，来源与证据候选才会成为当前私有修订，批次状态变为 `已合并`；证据的发布状态和来源允许用途保持原值，不会自动生成公开投射。当前尚未实现整批退回接口。

Agent 不得直接编辑 `ledger.json` 创建批次，也不得把研究候选直接写入当前记录来绕过人工裁定。

## 4. 日常人工维护流程

当前可用流程：

1. 启动开发环境：

   ```bash
   npm run dev
   ```

2. 在本机打开：

   ```text
   http://localhost:3000/sources
   ```

3. 搜索并选择楼盘。
4. 先登记来源，填写发布者、原始链接、来源类型、许可状态和允许用途。
5. 再创建字段证据，填写字段、值、来源、置信度、发布状态、观察日期和复核日期。
6. 信息未经用户裁定时，发布状态使用 `待裁定`；许可不明确时，来源用途使用 `仅限本地研究` 或 `仅限事实核验`。
7. 保存后确认当前修订号增加，且页面刷新后值仍然存在。
8. 在完成一个明确研究范围后，使用“冻结当前研究版本”保存修订集合。
9. 在“检查版本与公开预览”中选择版本，逐条处理未公开原因。
10. 只有用户已经人工复核该版本、且版本至少包含一个合格字段时，才可勾选确认并点击“生成公开数据”。
11. 生成后检查 `src/data/project-public-projection.json` 的 Git diff，并刷新楼盘详情页核对展示结果。

不要直接编辑 `outputs/source-ledger/ledger.json`。所有写入应通过资料中心或经过同一验证模块的脚本完成，以保留不可变修订和结构校验。

## 5. Agent 研究流程

### 5.1 Agent 可以做什么

- 查找符合授权和访问规则的候选来源
- 记录来源标题、发布者、链接、观察日期和许可判断
- 针对具体楼盘和字段形成候选值
- 标明置信度、冲突和后续核验任务
- 将未核验内容保持为 `待裁定` 或 `仅本地研究`
- 提交一份范围明确的候选清单供用户审核

### 5.2 Agent 不可以做什么

- 未经用户裁定自行标记为 `可公开投射`
- 因为来源是公开网页就默认允许复制或公开引用
- 把小红书帖子、评论或商业平台宣传直接当作项目事实
- 批量抓取、保存或复刻受限平台内容
- 提交 Cookie、Token、用户标识、完整帖子或私有研究备注
- 覆盖历史修订
- 直接修改生成的公开数据来绕过来源和证据模型

### 5.3 导入待裁定研究批次

先把候选整理为受验证的 JSON 清单，保存在被 Git 忽略的本地目录，例如：

```text
outputs/source-ledger/imports/<batch-name>.json
```

清单必须包含范围明确的：

- 批次目标和覆盖楼盘
- 候选来源及许可判断
- 候选字段和值
- 观察日期和建议复核日期
- 置信度
- 建议发布状态
- 冲突或待核验事项

先只校验清单：

```bash
npm run import:source-ledger-research-batch -- \
  --input outputs/source-ledger/imports/<batch-name>.json \
  --check
```

校验通过后再导入：

```bash
npm run import:source-ledger-research-batch -- \
  --input outputs/source-ledger/imports/<batch-name>.json
```

导入后在 `http://localhost:3000/sources` 的“研究验收版本”区域验收。导入器通过与资料中心相同的结构校验创建批次；不得用直接修改 `ledger.json` 的方式代替。

Agent 必须等待用户完成全部候选验收或明确授权整批验收，才能点击“并入当前台账”。合并只会创建当前私有来源和证据修订；不能因为验收或合并而把候选改成 `可公开投射`，也不能直接写入公开产品数据。

## 6. 公开发布流程

目标流程是：

```text
Agent 候选
  → 用户裁定
  → 当前私有来源/证据修订
  → 资料版本
  → 生成公开投射
  → 校验脱敏与新鲜度
  → 提交 src/data 中的公开数据
  → 地图与楼盘详情页消费
```

当前已实现：

- 私有来源和证据编辑
- 不可变修订
- 待裁定研究批次的受验证导入
- 研究批次浏览、搜索、未验收筛选和逐条验收进度
- 全部验收后的研究批次整批合并
- 资料版本创建
- 公开资格、新鲜度和来源用途筛选
- 私有备注与修订信息脱敏
- 指定资料版本、显式确认人工审核后生成公开文件
- 资料版本浏览、逐条公开资格诊断和真实公开文件状态展示
- 本地资料中心内受人工确认保护的“生成公开数据”操作
- 校验公开文件与冻结资料版本一致
- 楼盘详情页读取公开投射字段
- 本地路由与生产构建隔离

当前尚未实现：

- 研究批次整批退回
- 资料版本恢复

生成公开投射前，用户必须已经审核目标资料版本。执行：

```bash
npm run build:public-project-data -- \
  --snapshot <ledger-snapshot-id> \
  --confirm-reviewed
```

也可以在本地资料中心选择冻结版本、核对公开预览、勾选人工复核确认后点击“生成公开数据”。该操作和命令行生成器使用相同的冻结版本与公开资格规则；没有合格字段时不会覆盖现有公开文件。

生成后必须检查 Git diff，确认只包含允许公开的最小字段，再运行完整验证并提交 `src/data/project-public-projection.json`。

本机有私有底稿时，还必须核对公开文件与冻结资料版本完全一致：

```bash
npm run check:public-project-data-source
```

CI 和没有私有底稿的环境运行 `npm run check:public-project-data`，只验证公开文件结构；它不能替代本机来源一致性检查。

Agent 没有收到明确人工审核确认时，不得运行以上生成命令，也不能宣称新字段已经发布到地图 APP。

## 7. 修改代码后的验证

至少运行：

```bash
node --test src/lib/source-ledger.test.ts
npm run check:public-project-data
npm run typecheck
npm run lint
npm run check:public
npm run build
```

如果修改地图项目显示、搜索、详情卡片或聚合行为，还要运行：

```bash
npm run check:map-performance
```

还必须验证：

- 开发环境 `/sources` 可以读取和保存
- 页面刷新后资料仍存在
- 桌面和移动端没有明显布局问题
- 生产构建中的 `/sources` 和 `/api/source-ledger` 返回 404
- `git status --ignored` 显示 `outputs/source-ledger/` 仍被忽略
- 提交中没有 `ledger.json`、私有备注、受限摘录或认证信息

## 8. 故障与恢复

- JSON 不存在时，系统会创建空的 schema v1 资料库。
- JSON 无法通过解析时，停止写入并报告具体校验错误；不得用空文件覆盖。
- 写入使用临时文件和原子重命名，避免部分写入。
- 当前没有自动备份、跨设备同步或快照恢复接口。
- 需要迁移、恢复或修复损坏数据时，先复制原文件到工作区外的安全位置，再编写经过测试的一次性迁移工具。

## 9. Agent 完成检查单

提交结果前确认：

- [ ] 已读取所有适用指南
- [ ] 楼盘 ID 来自固定公开目录
- [ ] 来源先于证据登记
- [ ] 来源许可与证据置信度分别判断
- [ ] 未经人工裁定的记录没有标记为 `可公开投射`
- [ ] 历史修订没有被覆盖或删除
- [ ] 私有文件和认证信息没有进入 Git
- [ ] 公开字段未超过复核日期
- [ ] 公开投射来自明确审核过的资料版本
- [ ] 已运行适用测试
- [ ] 已准确说明哪些内容只在本地、哪些已经进入公开 APP
