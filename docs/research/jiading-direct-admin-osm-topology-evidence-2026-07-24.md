# 嘉定 8 个直接行政骨架的固定 OSM 拓扑证据

日期：2026-07-24

对象：江桥、南翔、马陆、徐行、外冈、安亭、华亭、菊园新区。

## 一、结论

本文件只核对项目锁定的本地 OSM GPKG，不使用政府面积、卖方项目归属或其他外部材料，因此只能回答“固定开放快照中有什么行政几何、这些几何如何相接”，不能证明楼市板块边界。

- 江桥、南翔、马陆、徐行、外冈、安亭、华亭各能唯一映射到一个去掉行政类型后同名的 `admin_level8` relation；
- **菊园新区没有唯一、有效、同名的行政 relation**。固定快照只找到 `菊园街道` relation `17000643`；它可以作为待核行政代理，但不能写成“同名行政骨架”；
- 8 个几何都非空、有效，在 EPSG:32651 下均为一个组成面的无洞 `MultiPolygon`，同批之间没有正面积重叠；
- 同批存在 12 组直接共享边，适合按一个拓扑批次生成；
- 与已完成候选直接相接的边包括华新、白鹤、桃浦、顾村、罗店、罗泾；徐泾和虹桥商务区均不直接接触本批；
- 固定快照还显示娄塘镇、嘉定镇街道、新成路街道、真新街道、华漕镇、新泾镇、大场镇等批外邻接单元。它们不能被这 8 个面静默吸收，尤其娄塘镇会在嘉定北部总装中留下显著未分配区域。

固定层字段把本批几何标为：

```text

```

面积、边长、重叠和距离均投影到 EPSG:32651 后计算。共享边采用两个原始 GPKG relation 边界的几何交集长度；跨批次与当前 `reviewed-candidates.wgs84.json` 的组装检查另采用 `0.1 m` 容差，以吸收 WGS84 JSON 序列化造成的亚分米坐标差。容差检查不是把相距较远的边强行吸附。

## 七、生成建议

前 7 项可以采用：

```text
status = reviewed-candidate
confidence = low
method = market_admin_candidate_with_shared_topology
marketAdminAlignmentUnverified = true
```

菊园新区如要在本轮生成，必须另加：

```text
adminProxyName = 菊园街道
marketAdminAlignmentUnverified = true
riskFlags += admin_name_mismatch
```

并在说明中明确“市场菊园新区暂借菊园街道 relation 起画”，不得把 relation 名改写成“菊园新区”，也不得把名称不一致藏在别名字段里。

建议验收门槛：

1. relation ID 和预期 OSM 名称逐项固定，不做模糊自动匹配；
2. GPKG SHA-256 不一致时停止生成；
3. 保留完整 MultiPolygon 语义及所有部件/洞，即使本快照均为单部件无洞；
4. 8 面全部有效、非空，同批正面积重叠为零；
5. 本文件第四节 12 组同批共享边逐对登记并验证；
6. 本文件第五节 11 组跨批次候选接口按 `0.1 m` 容差联合验证；
7. 不给徐泾、虹桥商务区添加虚假的直接邻接；
8. 娄塘镇及嘉定核心、丰庄、华漕、真新、新泾、大场接口保持显式未解决；
9. 菊园新区在取得行政名称/市场范围独立证据前，不得升级为“同名行政对齐”；
10. 本地 OSM 几何仅作为开放行政候选，不得表述成法定行政边界、卖方专有边界或行业统一楼市板块。

## 八、本研究明确不主张

- 不主张 8 个行政几何就是楼市板块；
- 不主张 OSM relation 是法定行政界线；
- 不主张 `菊园街道` 与“菊园新区”名称或范围等同；
- 不主张面积大或拓扑连续能够证明市场范围准确；
- 不主张徐泾、虹桥商务区与本批存在直接共享边；
- 不主张用这 8 面能够完整覆盖嘉定市场，尤其不能掩盖娄塘镇和嘉定核心空档；
- 不主张把批外行政邻接直接升级为市场邻接；
- 不主张本文件使用了任何卖方专有 polygon 或外部边界数据。
