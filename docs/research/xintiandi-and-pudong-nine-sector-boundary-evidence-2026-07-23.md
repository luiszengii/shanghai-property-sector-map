# 新天地缺口与浦东东南九板块边界证据

核验日期：2026-07-23
用途：为 `sector_xintiandi` 以及下一批 9 个浦东市场板块提供可审计的起画口径；不复制商业地图 polygon。
本批推荐：康桥、周浦、航头、新场、川沙、唐镇、宣桥、惠南、祝桥。

## 结论

1. 黄浦现有九块围住的缺口在行政拓扑上就是**淮海中路街道**，不是官方狭义“新天地地区”的边界。
2. “淮海中路街道”“新天地地区”“上海新天地项目”“链家新天地商圈”是四种不同对象。链家甚至同时列出“淮海中路”和“新天地”，不能引用链家证明两者天然同义。
3. 但本项目主清单已经把“淮海中路”并入“新天地”，用户这次又明确要求把被围住的完整缺口补成新天地。因此，最可审计的产品实现是：**以完整淮海中路街道 relation 12236003 填合缺口，产品名为“新天地”，状态保持“市场身份 + 行政骨架候选”**。这是一项产品建模决策，不是对行业统一边界的宣称。
4. 紧接着应绘制 9 个此前没有精确候选面的浦东板块：**康桥、周浦、航头、新场、川沙、唐镇、宣桥、惠南、祝桥**。不要用已经存在、只是需要精修的张江或金桥来充抵“8-10 个新板块”。
5. 九个浦东名称都同时出现在上海市民政局街镇名单和链家公开市场目录中，适合先用同名行政镇关系生成一套连续、零重叠、可编辑的保守骨架；它们仍不能标成行业统一的最终市场边界。

关键事实是：官方 2024 年管理办法把新天地管理机构办公室设在淮海中路街道办事处，但这仍只说明管理关系，不说明两个范围相等。瑞安项目约 0.52 km²，也明显小于 1.41 km² 的完整街道。

### 2. 为什么仍推荐用完整缺口作为产品“新天地”

这是由本项目当前产品口径和拓扑目标共同决定的：

- 主清单目前只保留“新天地”为黄浦一级板块，并把“淮海中路”作为其合并标签；
- 用户指认的是九块之间“被围起来的那一个”，对应完整淮海中路街道，不是狭义项目核心；
- 黄浦前九块同样使用街道 relation 作为保守市场骨架；第十块使用同源 relation，能复用同一组边界节点，避免再次人工估线；
- 如果只画官方 2024 新天地管理区，淮海中路街道西部、北部和南部会继续留下三个无归属空洞，不满足这次“补上被围住缺口”的要求。

因此建议定义：

| 字段 | 建议 |
|---|---|
| `id` | `sector_xintiandi` |
| `canonicalName` | `新天地` |
| `expectedOsmName` | `淮海中路街道` |
| 起画 relation | [OSM relation 12236003](https://www.openstreetmap.org/relation/12236003) |
| 方法 | `market_admin_candidate_with_shared_topology` |
| 产品别名 | `淮海中路`，但 UI 说明它是合并搜索标签，不是同义边界事实 |
| 候选等级 | 内部审核 / 行政骨架市场候选；不能标为“官方新天地边界” |
| 官方面积校验 | 约 1.41 km²；固定快照生成结果应落在 1.35-1.50 km² |
| 相邻候选 | 瑞金二路、打浦桥、老西门、豫园、南京东路，以及与外滩约 113 米的短共享边 |

### 3. 生成与验收方法

1. 使用与黄浦九块相同的锁定 Geofabrik/OSM 快照，固定 relation `12236003`，输出 WGS84；
2. 与周围黄浦 relation 同批总装，禁止每块独立简化或重画共享边；
3. 候选与黄浦九块两两面积重叠必须为 0；十块 union 不应出现内部空洞；
4. 当前固定候选在 EPSG:32651 下复算得到六条共享边：瑞金二路约 1,452 米、打浦桥约 932 米、老西门约 780 米、豫园约 800 米、外滩约 113 米、南京东路约 973 米；生成后必须逐条回归，只在点上接触时不能虚报为共享边；
5. 在证据备注中并列保存 2024 官方管理范围和瑞安 52 公顷项目口径，但不要用它们替换完整候选面；
6. 后续若项目归属抽样证明“淮海中路”应恢复为独立一级板块，再通过 ADR 拆分，不能无记录改名。

## 二、为什么下一批选这九个

仓库当前已经有精确候选的 22 块不应重复绘制。张江、金桥已经登记为“已有但需要精修”，也不应拿来充抵用户要求的 8-10 个新板块。

推荐九块在空间上形成两个互相连接的官方城镇圈：

- 浦江-周浦-康桥-航头整合提升型城镇圈：康桥、周浦、航头，并向新场、川沙连接；
- 祝桥-惠南综合发展型城镇圈：祝桥、惠南、宣桥，并统筹新场；
- 唐镇通过川沙把北部张江/金桥边界与东南组连接起来。

依据为[《上海市浦东新区国土空间总体规划（2017-2035）》](https://ghzyj.sh.gov.cn/cmsres/91/9144335385054517a70ed9f8b558f900/4acf8db94cdca43b3a6c567da5a77b5a.pdf)。这能证明它们适合做同一拓扑批次，但不能证明市场边界等于行政镇界。

市场身份方面，[链家上海网站地图](https://sh.lianjia.com/seositemap/)明确列出川沙、航头、惠南、唐镇、新场、宣桥、周浦、祝桥；“康桥”也有独立入口，但 sitemap 把它误排在“闵行”分组下，而[贝壳新房页面](https://sh.fang.ke.com/loupan/p_zsyxbmjev/)又把康桥列在浦东目录中。由此只能确认“康桥”是市场标签，不能信任 sitemap 的行政分组或据此推断边界。

### 不能混淆的规划数字

- 康桥 41.55 km²、周浦 42.68 km²、唐镇 32.32 km²、川沙 95.35 km²是各自规划中的全镇口径；
- 航头 50.69 km²和宣桥 34.96 km²只覆盖“大治河以北”，不能拿来校验完整行政 relation 的面积；
- 惠南 65.78 km²是全镇，35.58 km²是城镇开发边界；
- 祝桥 160.19 km²是现行镇域，83.47 km²是 2019 总规中的城镇开发边界；
- 新场非工业城镇单元约 7.19 km²，只是推荐的后续市场核心审查范围，不是已确认市场 polygon。

## 四、推荐拓扑关系

本批应作为一个拓扑组生成。根据官方规划文字和现行行政关系，至少核验下列内部共享边：

1. 康桥-周浦
2. 康桥-川沙
3. 周浦-航头
4. 周浦-新场
5. 周浦-川沙
6. 航头-新场
7. 新场-川沙
8. 新场-宣桥
9. 川沙-唐镇
10. 川沙-宣桥
11. 川沙-祝桥
12. 宣桥-惠南
13. 宣桥-祝桥
14. 惠南-祝桥

这张表是生成前的核验清单，不是法定界线长度清单。固定快照总装后必须以实际 `intersection(boundaryA, boundaryB)` 复算；只有点接触而没有线长的组合不能写入 `sharedEdgeSectorIds`。

对外衔接还需核验：

- 康桥与既有三林、御桥、北蔡/张江参考边；
- 唐镇与既有张江、金桥参考边；
- 2025 年官方公告已经明确调整川沙-祝桥、北蔡-康桥等局部线位，[公告](https://www.pudong.gov.cn/zwgk/qt-qzf/2025/325/348121.html)优先于更旧的规划图和 OSM 旧快照；
- 本批南部、东部未纳入的相邻镇保持开放边，不单方面冻结大团、老港、合庆等后续板块。

## 五、推荐实施顺序与验收门槛

### 实施顺序

1. 先补新天地，并单独验证黄浦十块 union 无内部空洞；
2. 锁定九个浦东 relation ID、快照时间、SHA-256、WGS84 与 ODbL 署名；
3. 一次性生成九块行政骨架，不能九个 agent 各自描一套共享边；
4. 先固定北部锚点康桥-周浦-川沙-唐镇，再向南拼航头-新场-宣桥-惠南-祝桥；
5. 在注册表中全部使用“行政骨架市场候选”状态；祝桥、川沙、唐镇尤其不能标成高置信市场边界；
6. 后续通过编辑器按官方主城区/城镇单元和完整项目归属逐块收窄，任何共享边修改必须同步更新两侧。

### 最低验收

- 新天地 + 9 个浦东板块全部生成有效 Polygon/MultiPolygon；
- 每块都有固定 relation、官方名称来源、市场名称来源、几何来源和风险说明；
- 同批任意两块面积重叠为 0；
- 声明的共享边都测得非零线长，未声明的两块不应出现明显面积重叠；
- 新场-川沙固定 relation 当前实测约 1.1 km 共享边，应保留并做回归；
- 川沙-祝桥使用 2025 公告线位或明确记录尚未合入公告调整；
- 生成结果能在主地图显示、搜索、打开详情，并能在编辑器独立修改；
- 文案不得出现“官方楼市板块边界”“行业统一边界”或把规划开发边界写成市场边界。

## 六、证据边界

- 官方规划和民政资料可以证明行政名称、规划版本、规划范围、功能片区与部分四至，不能证明楼市板块 polygon；
- OSM relation 可以提供可复现的 WGS84 起画坐标和共享节点，不是法定界址；
- 链家/贝壳目录只能证明市场标签存在，不能复制其地图边界，也不能仅凭目录分组裁区；
- 本文没有读取或使用小红书原始数据，没有复制任何商业地图 polygon；
- 所有候选仍应保留人工编辑入口和逐边来源记录。
