# RealtyNavi 低噪音地图与板块边界许可核查

> 观察日期：2026-07-28
>
> 目标：
>
> 1. 核对高德地图 Web JS API 是否能隐藏普通商业 POI，只保留或自建地铁、医院、学校和楼盘图层。
> 2. 核对 `realtynavi.com` 的板块边界即使能由网页前端取得，是否有明确许可允许复制、保存并作为本项目的第四个边界对照。
>
> 取证边界：高德部分只使用高德官方文档、服务协议、价格页和合规指南；RealtyNavi 部分只使用目标站自己的首页、服务协议、版权页和无需登录即可取得的公开 HTML/JavaScript 响应。没有批量抓取，没有请求、保存、输出或复刻任何 polygon 坐标，也没有绕过登录或访问控制。

## 授权与下载状态更新（2026-07-28）

用户随后确认已经取得 RealtyNavi 板块边界数据的下载和内部对照授权。本项目据此按以下范围执行：

- 仅作为本机内部研究的第四套边界对照；
- 不进入公开构建，不对外分发；
- 授权文件本身不进入 Git，本报告只记录用户的授权确认；
- 通过站方公开网页客户端的正常接口流程低频请求上海 16 区，没有登录、验证码、风控规避或批量分页。

本次取得 151 / 151 个板块边界，源坐标系为 GCJ-02，生成物为：

```text
outputs/realtynavi/shanghai-sector-boundaries-raw-2026-07-28.json
outputs/realtynavi/shanghai-sector-boundaries-gcj02-2026-07-28.geojson
```

两份文件和下载辅助脚本都位于 Git 忽略的 `outputs/realtynavi/`。快照元数据记录抓取时间、接口、客户端资源哈希、授权确认、用途限制、区县数、板块数和坐标系。下文“许可上不可用”的判断是取得授权前的历史核查结论，保留用于说明当时的决策依据。

### 区级外轮廓差异参考层（2026-07-29）

源接口返回的 151 个板块全部具有名称，名称集合没有缺失；151 个标签点也全部位于各自 polygon 内。内部对照层保留这些命名板块的原始身份和边界，另以“区级外轮廓减去该区全部命名板块并集”的方式，为上海 16 区各生成一个“××区级外轮廓差异范围”参考面。

这些差异范围不是 RealtyNavi 的未命名板块。诊断得到 4639 个差异碎片，按面积计算 99.49% 与区级外边界相接，主要表达区级外轮廓与楼市板块外缘口径不一致。它们默认关闭、单独作为灰色虚线参考层显示，不计入 151 个板块数量，也不会登记到项目的公开板块身份表。生成时同时按 RealtyNavi 客户端行为剔除每个命名板块坐标数组的首尾哨兵点，避免混淆坐标参与几何绘制。

## 结论

### RealtyNavi 的地图是否真的只显示四类点

**不是。它主要依赖高德标准底图自身的缩放分级和标签避让，再叠加站方楼盘、房价等高线和板块覆盖物。**

2026-07-28 在首页由上海全市逐级放大到中心城区后，底图仍能看到公园、政府机构、银行、酒店、商场、文化设施等标签，并非只保留地铁、医院、学校和楼盘。页面加载高德 Web JS API `v=1.4.4`；首页编译代码创建 `el-amap` 时传入中心点、缩放、缩放范围、事件和插件，没有传入 `mapStyle`、`features` 或 `showLabel`。网络侧还加载了高德标准样式图标资源。因此现有证据更支持“高德标准底图 + 默认标签层级/避让”，而不是站方制作了一套只保留四类 POI 的自定义底图。

站方额外叠加的内容包括：

- 蓝色新房楼盘 Marker 和缩放后的楼盘聚合；
- 房价等高线 polygon；
- 区域/环线 polygon 与地铁 polyline；
- 区域、环线、地铁和楼盘状态筛选。

来源：[RealtyNavi 首页](https://www.realtynavi.com/)；[公开主 JavaScript 资源](https://www.realtynavi.com/static/js/b050e3f1.16827909.js)（观察：2026-07-28）

### 高德能否做出类似的低噪音地图

**能，而且当前产品的代码结构已经具备大部分条件。**

推荐实现不是让高德原生底图“碰巧只显示四类 POI”，而是：

1. 把高德作为低噪音的道路、区域面和可选建筑底图；
2. 关闭高德底图的全部普通 POI，或用 GeoHUB 自定义地图按 POI 类别隐藏；
3. 继续用项目自己的 `ProjectLayer` 展示已裁定楼盘；
4. 用项目自己的专题图层展示许可明确的地铁、医院和学校数据。

高德 `Map.setFeatures()` 只把底图分成 `bg`、`point`、`road`、`building` 四类，其中 `point` 代表全部兴趣点。因此它可以一次关闭所有 POI，但不能通过这一方法做到“隐藏餐饮商店、保留学校医院”。[高德地图 JS API 2.0 自定义地图教程](https://lbs.amap.com/api/javascript-api-v2/guide/map/map-style)（最后更新：2024-01-22；观察：2026-07-28）

若要在高德底图内按 POI 类别控制，官方 GeoHUB 自定义地图是对应能力。高德产品页称可定制 7 大类、44 种地图元素；官方 FAQ 进一步说明，“兴趣点”按类别单独配置属性目前在 JS API 端生效。[高德自定义地图产品页](https://lbs.amap.com/product/mapstyle)；[高德自定义地图 FAQ](https://lbs.amap.com/faq/maplab/mapstyle/call-map/51788)（观察：2026-07-28）

### RealtyNavi 板块边界能否作为第四套本地对照

**现状是技术上可见、许可上不可用。**

目标站公开前端代码显示，板块覆盖物的坐标会由站方接口返回给浏览器并保存到前端状态，用于绘制“区域下板块覆盖物”。这说明浏览器为了正常渲染确实会接收边界数据；但站方没有提供公开数据下载页、开放数据许可或允许本项目复制保存的授权。[RealtyNavi 首页](https://www.realtynavi.com/)；[公开主 JavaScript 资源](https://www.realtynavi.com/static/js/b050e3f1.16827909.js)（HTTP 200，`application/javascript`；观察：2026-07-28）

RealtyNavi 的服务协议明确把“数据资料、图形、图表”和客户端—服务端交互数据纳入保护范围，并在没有书面许可时禁止复制、读取、下载、抓取、使用或制作衍生内容；知识产权条款又要求复制、下载、引用、链接或抓取平台资料取得明确的特别书面许可。[RealtyNavi 服务协议](https://www.realtynavi.com/serveDeal/)（协议标示生效日：2021-12-02；观察：2026-07-28）

因此，在没有站方书面数据许可之前：

- 不应下载或保存其 polygon；
- 不应把其坐标加入本地研究底稿；
- 不应把其形状作为第四套逐点或量化几何对照；
- 不应通过截图、接口响应或浏览器内存重建边界。

仍可把 RealtyNavi 当作**产品交互、板块名称、市场语义、相邻关系和大致形态**的人工研究线索；可发布坐标继续从固定且许可明确的 OSM/Geofabrik 快照等来源独立生成。

## 一、高德低噪音地图：能力拆解

### 1. `setFeatures` 适合“一刀切关闭 POI”

官方教程列出的底图要素只有：

| 要素 | 含义 | 对本项目的作用 |
|---|---|---|
| `bg` | 区域面 | 保留 |
| `road` | 道路及道路标注 | 保留 |
| `building` | 建筑物 | 可按视觉密度选择 |
| `point` | 兴趣点 | 关闭后会同时移除商业、学校、医院等原生 POI |

来源：[高德地图 JS API 2.0 自定义地图教程](https://lbs.amap.com/api/javascript-api-v2/guide/map/map-style)（观察：2026-07-28）

所以最快的实现可以是：

```ts
const map = new AMap.Map(container, {
  mapStyle: "amap://styles/whitesmoke",
  features: ["bg", "road", "building"],
});
```

具体是否保留 `building` 应在上海市级、板块级和楼盘级三个缩放档实际验收。此示例表达能力边界，不代表已经在本仓库实施。

### 2. GeoHUB 自定义样式适合“按 POI 类别减法”

高德允许在自定义地图平台创建、编辑和发布样式，取得样式 ID 后通过 `amap://styles/样式ID` 加载。[高德自定义地图教程](https://lbs.amap.com/api/javascript-api-v2/guide/map/map-style)（观察：2026-07-28）

官方资料能够支持的结论是：

- GeoHUB 支持多类地图元素定制；
- JS API 端支持对“兴趣点”按类别单独配置属性；
- 因而可以在样式层隐藏餐饮、购物、生活服务等小商业 POI。

来源：[高德自定义地图产品页](https://lbs.amap.com/product/mapstyle)；[高德自定义地图 FAQ](https://lbs.amap.com/faq/maplab/mapstyle/call-map/51788)（观察：2026-07-28）

官方公开页没有完整列出当前免费套餐 42 个可修改元素在编辑器中的逐项名称。因此，“学校、医院、地铁站能否以期望的标签层级和缩放阈值保留”仍需登录 GeoHUB 编辑器创建样式后做一次真实视觉验收，不能仅凭产品页宣称已经完成。

### 3. 地铁、医院和学校可用在线搜索补充，但不宜扫库保存

`AMap.PlaceSearch` 支持通过 `type` 筛选 POI 类别，多个类别可用 `|` 分隔；指定 `map` 后，搜索结果可以自动添加到地图。其公开参考手册同时给出每页 1–50 条、页码 1–100 的范围。[高德 PlaceSearch 参考手册](https://lbs.amap.com/api/maps-javascript-api/reference/search/placesearch)（最后更新：2026-07-02；观察：2026-07-28）

这适合：

- 按当前视窗或用户查询即时展示学校、医院、地铁站；
- 作为专题数据缺口的在线补充；
- 在地图交互中显示，不把结果沉淀成自有数据资产。

这不适合：

- 把上海全市网格化扫一遍；
- 将搜索结果长期缓存到 `src/data/`；
- 把返回结果当作完整、权威的设施名录。

高德服务协议第 3.5 条规定，只能使用官方开放功能展示服务数据结果，不得直接存储、缓存或以技术手段抓取内部数据；脱离服务使用需要提交工单评估。[高德地图开放平台服务协议](https://lbs.amap.com/pages/terms/)（观察：2026-07-28）

高德 POI 分类编码页也明确说明编码表会不定期更新，只供查询，不应作为缓存文件或把数字编码写死在程序中。[高德 Web 服务 API 相关下载](https://lbs.amap.com/api/webservice/download)（最后更新：2026-04-30；观察：2026-07-28）

### 4. “住宅小区 POI”不等于本产品的楼盘资料

高德分类中存在商务住宅、住宅区、住宅小区等 POI，但它们不能证明：

- 项目是否当前在售；
- 项目分期和官方名称；
- 当前价格、交付状态或销售状态；
- 是否已经通过本项目的来源与发布裁定。

高德服务协议也说明地图、搜索及 POI 详情仅供参考，可能与现实不完全一致。[高德地图开放平台服务协议](https://lbs.amap.com/pages/terms/)（观察：2026-07-28）

因此楼盘层应继续使用本项目已裁定的公开项目数据，不用高德“住宅小区”结果替换。高德分类只适合在线查询或辅助定位。

### 5. 高德“地铁图 JS API”不是普通地图上的现成地铁线图层

高德将地铁图 JS API 定位为移动端 H5 地铁线路图接口，提供线路展示、站点标注、路线查询和规划；该产品仍标为 Beta。[高德地铁图 JS API 概述](https://lbs.amap.com/api/subway-api/subway-summary/)（最后更新：2025-12-03；观察：2026-07-28）

它不是在普通地理底图上直接叠加真实地理位置轨道线的通用图层。若产品目标是类似 RealtyNavi 的城市地图，推荐：

- 站点：用许可明确的自有数据，或视窗内即时 `PlaceSearch`；
- 线路：用许可明确、版本锁定的地铁几何作为自建 `Polyline`/GeoJSON 图层；
- 不把独立 H5 地铁示意图误当作地图主页面的线路数据源。

## 二、结合当前仓库的最短实施路径

本次只做研究，没有修改代码。只读检查显示：

- `src/components/map/MapContainer.tsx` 当前使用 `mapStyle: "amap://styles/normal"` 和 `showLabel: true`，因此高德普通 POI 标签仍会出现；
- `src/components/map/ProjectLayer.tsx` 已经用项目自己的楼盘数据和 Marker 渲染楼盘；
- `src/components/map/PlaceLayer.tsx` 已经能按类别渲染自有设施 Marker；
- `src/data/places.json` 当前学校、医院、地铁等记录仍是明确标注的演示数据，不能直接当作真实设施资料发布。

### 方案 A：最快、最可控

1. 主地图用 `features: ["bg", "road", "building"]` 关闭全部高德 POI；
2. 继续使用现有 `ProjectLayer`；
3. 用许可明确且经过来源治理的数据替换 `places.json` 演示点；
4. 在现有 `PlaceLayer` 中只启用 `school`、`hospital`、`metro`；
5. 需要地铁线时另建独立线路图层。

优点是视觉最稳定、规则最容易解释，也不会因为高德样式调整让小商业重新出现。

### 方案 B：更接近 RealtyNavi 的原生底图观感

1. 在 GeoHUB 创建项目专用样式；
2. 关闭商业、餐饮、购物和生活服务 POI；
3. 试验保留交通、医疗和教育类底图 POI；
4. 楼盘仍由 `ProjectLayer` 自建；
5. 用不同缩放档检查标签数量、层级和重叠。

优点是可以利用高德原生标签；缺点是样式分类、缩放显隐和高德数据更新都需要持续验收。

### 推荐顺序

先做方案 A 的视觉样片，确认道路、行政名称和建筑层是否足够；再决定是否值得增加 GeoHUB 类别配置。无论选哪种，楼盘都保持为项目自有专题层。

## 三、高德费用、许可和地图合规

以下价格和配额会调整，应在真正上线或扩大流量前重新核对。

高德 JS API 概述称，非商业目的可以免费使用；商业目的需事先取得商用授权。服务协议进一步规定，法人或非法人组织使用，以及直接或间接获取收益等商业场景，需要事先购买技术服务许可。[高德 JS API 概述](https://lbs.amap.com/api/JavaScript-api/summary)；[高德服务协议](https://lbs.amap.com/pages/terms/)（观察：2026-07-28）

当前官方价格页显示：

- 基础搜索服务：30 元/万次；

### 存储和缓存限制

不应把 `PlaceSearch` 当作本地设施数据库的批量采集接口。高德协议禁止直接存储、缓存或抓取服务内部数据；若需要脱离高德服务使用，应通过工单确认合作许可。[高德服务协议](https://lbs.amap.com/pages/terms/)（观察：2026-07-28）

### 地图审图号与来源标示

高德合规指南要求引用地图时注明地图来源和审图号；若修改所调用地图内容，还应注意依法履行地图审核程序。[高德开发者合规指南](https://lbs.amap.com/api/compliance-center/check-and-reference/compliance)（最后更新：2025-12-03；观察：2026-07-28）

自建楼盘、设施和市场板块专题层与高德底图组合发布时，应在上线前做一次地图合规自查。本报告不是法律意见。

## 四、RealtyNavi 边界技术可见性与许可

### 公开技术响应观察

2026-07-28 的低频、公开响应检查得到：

- `https://www.realtynavi.com/` 返回 HTTP 200、`text/html`；
- 首页加载高德 Web JS API `v=1.4.4`，并加载站方主 JavaScript 资源；
- 公开主 JavaScript 资源返回 HTTP 200、`application/javascript`；
- 代码存在 `/plate` 页面路由；
- 代码中的 `getPlateGobal` 会请求 `newDisk/search/conditionStatistics/hotPlate`；
- 成功响应会读取 `coordinateVos`，写入 `plateGlobalCoordinate`，用于“区域下板块覆盖物”。

证据：[RealtyNavi 首页](https://www.realtynavi.com/)；[RealtyNavi 公开主 JavaScript 资源](https://www.realtynavi.com/static/js/b050e3f1.16827909.js)（观察：2026-07-28）

本次没有调用该板块接口，没有记录请求参数，没有读取响应体，也没有提取任何坐标。

这组证据只支持“浏览器渲染需要接收边界数据”，不支持：

- 站方提供了合法的数据下载服务；
- 该数据是开放数据；
- 数据可被本项目复制、缓存、转换或公开展示；
- 站方拥有全部底层数据的转授权权利。

### 目标站协议的直接限制

RealtyNavi 服务协议的操作含义如下：

| 协议内容 | 对本项目的影响 |
|---|---|
| 未经事先书面同意，不得商业性复制、传播站内数据 | 不能把板块边界拿来构建本产品 |
| 平台信息内容包括数据资料、图形、图表 | polygon 不因“只是坐标”而自动脱离保护范围 |
| 未经书面许可，不得通过机器人、蜘蛛等监视、复制、下载或获取内容 | 不能批量抓取边界 |

### 作为“第四个对照”的安全边界

| 用法 | 当前判断 |
|---|---|
| 人工观察是否存在某板块名称 | 可作为研究线索，仍需独立来源核验 |
| 人工理解板块大致位置、相邻关系 | 可作定性参考，不记录坐标 |
| 保存截图并逐点描边 | 不可 |
| 调用前端接口保存 polygon | 不可 |
| 计算其边界与本项目边界的面积/距离差 | 不可，因为这要求取得并保存坐标 |
| 取得站方明确书面许可后的离线对照 | 可重新评估，需核对授权范围和第三方权利链 |

因此它目前不能成为与 OSM、行政参考面、其他已获许可几何并列的“第四套边界坐标数据”；最多只能成为第四个**定性市场语义来源**。
